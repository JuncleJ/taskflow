# TaskFlow — первоначальная генерация проекта

Ты - Java Backend Developer.

Необходимо сгенерировать первую рабочую версию приложения TaskFlow для асинхронного выполнения фоновых задач.

Работай непосредственно в текущем репозитории.

## 1. Технологический стек

- Java 21, Eclipse Temurin
- Vert.x (актуальная стабильная совместимая версия)
- PostgreSQL
- Vert.x Reactive PostgreSQL Client
- Gradle Kotlin DSL
- JUnit 5
- Docker Compose
- HTML, CSS, JavaScript

Не использовать Spring Boot и Hibernate.

## 2. Функциональные требования

### Пользователи
Реализовать:
- Регистрацию.
- Авторизацию по логину и паролю.
- Безопасное хеширование паролей.
- Токенную аутентификацию.
- Изоляцию пользовательских задач.

Пользователь должен иметь доступ исключительно к собственным задачам и событиям их выполнения.

### Фоновые задачи

Реализовать REST API:

| Метод | Endpoint | Назначение |
|---|---|---|
| POST | /api/auth/register | Регистрация |
| POST | /api/auth/login | Авторизация |
| POST | /api/tasks | Создание и запуск задачи |
| GET | /api/tasks | Получение своих задач |
| GET | /api/tasks/:id | Получение задачи |
| GET | /api/tasks/:id/events | Подписка на прогресс через SSE |

Создание задачи должно немедленно возвращать HTTP 202 Accepted и идентификатор задачи, не дожидаясь её выполнения.

Каждая задача содержит:
- UUID.
- Идентификатор владельца.
- Тип задачи.
- Статус.
- Прогресс выполнения (0–100%).
- Время создания.
- Время начала выполнения.
- Время завершения.
- Описание ошибки при неуспешном выполнении.

Статусы:
- PENDING
- RUNNING
- COMPLETED
- FAILED

### Выполнение задач

Реализовать расширяемую архитектуру на основе интерфейса TaskHandler.

Добавление нового типа задачи не должно требовать изменения логики движка выполнения.

Реализовать два демонстрационных обработчика:

1. DEMO — имитация длительной операции с периодическим обновлением прогресса.
2. REPORT — имитация генерации отчёта в несколько этапов.

Требования:
- Асинхронное выполнение.
- Одновременная обработка нескольких задач.
- Ограниченное количество параллельно исполняемых задач.
- Отсутствие блокировок Vert.x Event Loop.
- Сохранение статусов и прогресса в PostgreSQL.

### Отслеживание прогресса

Использовать Server-Sent Events (SSE).

Клиент должен получать:
- Текущее состояние задачи при подключении.
- Изменения прогресса.
- Событие завершения.
- Событие ошибки.

Обеспечить проверку прав доступа и корректную обработку отключения клиента.

### Веб-интерфейс

Реализовать простой интерфейс без frontend-фреймворков.

Функциональность:
- Регистрация и авторизация.
- Запуск DEMO и REPORT.
- Просмотр списка своих задач.
- Отображение статуса и прогресса.
- Автоматическое обновление прогресса через SSE.

## 3. Архитектура

Логически разделить приложение на:
- HTTP Handlers / Routes
- Authentication
- Task Service
- Task Executor
- Task Handler Registry
- Persistence
- SSE Notifications

Не усложнять архитектуру ненужными абстракциями.

Создать таблицы пользователей и фоновых задач.

Использовать параметризованные SQL-запросы и неблокирующий PostgreSQL-клиент.

Описать и реализовать понятное поведение незавершённых задач при перезапуске приложения.
