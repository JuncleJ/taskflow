# TaskFlow — управление жизненным циклом задач

Проанализируй существующие TaskExecutor, TaskService, TaskHandler, REST API, SSE и хранение задач в PostgreSQL.

Реализуй отмену и удаление фоновых задач, сохраняя текущую архитектуру приложения.

## 1. Отмена фоновых задач

Добавь новый статус `CANCELLED`.

Реализуй endpoint:

`POST /api/tasks/:id/cancel`

Требования:
- Отмена доступна только владельцу задачи.
- Для PENDING задача должна исключаться из последующего выполнения.
- Для RUNNING реализуй cooperative cancellation — задача должна корректно завершать работу при запросе отмены.
- Не устанавливай статус CANCELLED до фактического прекращения выполнения.
- После отмены запрещены переходы в RUNNING, COMPLETED или FAILED.
- Корректно обрабатывай повторную отмену и попытку отмены уже завершённой задачи.
- Учитывай гонку между отменой и естественным завершением.
- Сохраняй состояние в PostgreSQL.
- Отправляй обновления статуса через SSE.
- Не блокируй Vert.x Event Loop.

При необходимости добавь промежуточное состояние `CANCELLING`, чтобы различать запрос отмены и её фактическое завершение.

## 2. Удаление задач

Реализуй endpoint:

`DELETE /api/tasks/:id`

Требования:
- Разреши удаление только COMPLETED, FAILED и CANCELLED.
- Запрети удаление активных задач.
- Пользователь может удалять только свои задачи.
- Используй физическое удаление из PostgreSQL.
- Корректно обрабатывай несуществующие задачи.
- Учти активные SSE-подписки на удаляемые задачи.
- После удаления задача должна исчезать из пользовательского интерфейса.
- Исключи гонку между удалением и изменением статуса задачи.

Ко всем операциям необходимо добавить логи
