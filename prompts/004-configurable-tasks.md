# TaskFlow — расширение типов фоновых задач

Проанализируй существующий механизм выполнения фоновых задач.

Добавь возможность настройки длительности DEMO и новый тип CPU_TASK, выполняющий реальные вычисления.

Сохраняй существующую архитектуру и механизм отмены задач.

## 1. Настраиваемая длительность DEMO

Добавь параметр `durationSeconds`.

Пример запроса:

```json
{
  "type": "DEMO",
  "durationSeconds": 20
}
```

Требования:
- По умолчанию 5 секунд.
- Допустимый диапазон от 1 до 300 секунд (5 мин).
- Некорректные значения возвращают HTTP 400.
- Сохраняй параметры задачи в PostgreSQL.
- Прогресс должен соответствовать заданной длительности.
- Используй неблокирующие таймеры Vert.x.
- Поддерживай отмену задачи во время выполнения.

## 2. Новый тип CPU_TASK

Реализуй задачу, выполняющую реальные CPU-intensive вычисления.

В качестве алгоритма используй подсчёт простых чисел в заданном диапазоне.

Пример:

```json
{
  "type": "CPU_TASK",
  "limit": 1000000
}
```

Требования:
- Выполняй вычисления вне Event Loop.
- Используй отдельный ограниченный пул потоков.
- Предусмотри конфигурируемое количество worker-потоков.
- Не создавай неограниченные очереди и потоки.
- Поддерживай одновременное выполнение нескольких CPU_TASK.
- Ограничь допустимое значение limit безопасным диапазоном, обоснуй выбранные границы.
- Реализуй периодическое обновление прогресса.
- Не выполняй SQL-запрос на каждой итерации вычислений.
- Сохраняй прогресс в PostgreSQL.
- Отправляй события через SSE.
- Реализуй cooperative cancellation.
- При отмене вычисления должны действительно прекращаться.
- Обеспечь корректное завершение worker pool при остановке приложения.

Обрати внимание на потокобезопасность при передаче событий из worker-потоков в Vert.x context.
